# 多平台平台上下文改造 Requirements

## 背景

当前 PC 端 V1 已将 TikTok 养号脚本产品化，Instagram、WhatsApp、抖音只作为平台预留存在。后续产品需要支持多个平台独立运营，但不希望左侧导航随着平台数量增长而膨胀。

本规格定义多平台改造方向：顶部提供全局平台选择器，左侧保持稳定功能菜单；页面结构按功能组织，工程内部按平台 adapter 隔离实现。

## 产品原则

- 用户心智：先选平台，再选功能。
- 左侧菜单保持稳定，不按平台拆二级菜单。
- 删除左侧【平台管理】菜单，但保留平台设置入口。
- 保留【养号任务】和【目标号互动】两个独立功能菜单。
- 页面结构不按平台分，文件结构按平台分。
- 平台之间数据、配置、任务、统计、日志互不污染。
- 所有关键数据必须有明确 `platform` 维度，不能依赖 `tiktok_101` 这类账号 ID 前缀推断平台。

## 范围

纳入范围：

- 顶部全局平台选择器。
- 平台设置入口迁移到顶部“更多平台 / 平台设置”。
- 左侧导航调整：去掉【平台管理】，保留稳定功能菜单。
- 页面平台作用域规则。
- 平台独立配置、账号、任务参数、评论池、调度、统计和日志。
- 平台能力矩阵和后端能力校验。
- 支持全平台视角的页面必须提供平台筛选。
- 前后端平台 adapter 结构。
- 旧 TikTok 配置和数据的兼容迁移策略。

不纳入范围：

- 一次性实现 Instagram、WhatsApp、抖音完整自动化。
- 云端多租户、团队权限、跨设备同步。
- 重写当前 TikTok 自动化行为策略。

## 用户角色

- 运营人员：切换平台，维护账号，启动任务，查看执行结果和统计。
- 技术维护人员：维护平台接入状态、平台能力、执行器、诊断信息和系统设置。

## R1 顶部全局平台选择器

应用必须在顶部状态区提供平台选择器。

平台选择器包含：

- TikTok
- Instagram
- WhatsApp
- 抖音
- 更多平台

行为要求：

- 当前平台是应用级上下文。
- 写操作页面严格跟随当前平台。
- 汇总页面默认展示全部平台，并在页面内提供平台筛选。
- 系统页面不受当前平台影响。
- “更多平台”提供平台设置入口。

验收：

- Given 用户点击顶部 TikTok，When 进入养号任务，Then 页面展示 TikTok 养号任务。
- Given 用户点击顶部 Instagram，When 进入账号管理，Then 页面只展示 Instagram 账号。
- Given 用户进入统计报表，Then 默认展示全部平台数据，并可筛选平台。
- Given 当前平台为 WhatsApp，When 进入目标号互动但 WhatsApp 不支持该功能，Then 页面展示清晰的不支持状态和接入说明。

## R2 左侧导航稳定

左侧导航不按平台拆分二级菜单。

目标导航：

- 首页
- 账号管理
- 浏览器环境
- 养号任务
- 目标号互动
- 调度计划
- 评论素材
- 执行记录
- Session 日志
- 统计报表
- Gmail 初始化
- 诊断工具
- 系统设置

【平台管理】从左侧移除。

验收：

- Given 应用启动，When 用户查看左侧导航，Then 不显示【平台管理】。
- Given 新增平台，When 用户查看左侧导航，Then 左侧导航不新增平台二级菜单。
- Given 用户切换平台，Then 左侧菜单选中状态不因平台切换丢失。

## R3 平台设置入口

平台设置不能消失，必须从顶部“更多平台 / 平台设置”进入。

平台设置内容：

- 平台列表。
- 平台启用/停用。
- 平台接入状态：已支持、预留、开发中、未支持。
- 平台能力矩阵。
- 平台默认配置入口。
- 平台 API / 环境说明。
- 新增平台注册入口或预留入口。

验收：

- Given 用户点击“更多平台”，Then 可以进入平台设置。
- Given 平台为预留状态，Then 启动类页面不能启动任务。
- Given 技术维护人员查看平台能力，Then 能看到该平台支持哪些功能。

## R4 平台独立数据

以下数据必须带 `platform` 维度：

- 账号。
- 浏览器 profile 绑定。
- 养号任务参数。
- 目标号互动配置。
- 评论池。
- 调度计划。
- 执行记录。
- Session 日志。
- 统计数据。
- 目标互动水位线。

验收：

- Given TikTok 和 Instagram 都有账号，When 编辑 TikTok 账号，Then Instagram 账号不受影响。
- Given TikTok 和抖音都有评论池，When 保存 TikTok 评论素材，Then 不覆盖抖音评论素材。
- Given 查询执行记录，When 筛选 TikTok，Then 不出现 Instagram 记录。

## R5 菜单平台作用域

菜单分为三类：严格当前平台、支持全平台视角、系统级页面。

严格当前平台：

- 账号管理
- 浏览器环境
- 养号任务
- 目标号互动
- 调度计划
- 评论素材
- Gmail 初始化

支持全平台视角：

- 首页
- 执行记录
- Session 日志
- 统计报表

系统级页面：

- 诊断工具
- 系统设置
- 平台设置

验收：

- Given 当前平台是 TikTok，When 打开养号任务，Then 只能操作 TikTok 任务。
- Given 打开执行记录，Then 默认展示全部平台记录，并提供平台筛选。
- Given 打开系统设置，Then 内容不随当前平台切换。

## R6 全平台视角筛选

支持全平台视角的页面必须提供平台筛选。

筛选要求：

- 首页：平台、时间范围。
- 执行记录：平台、账号、任务类型、状态、时间范围。
- Session 日志：平台、账号、任务类型、状态或关键词、时间范围。
- 统计报表：平台、账号、任务类型、时间范围。

验收：

- Given 执行记录存在多个平台数据，When 用户筛选 Instagram，Then 只展示 Instagram 数据。
- Given 用户清空平台筛选，Then 恢复全部平台数据。
- Given 用户筛选平台后再筛账号，Then 账号下拉只展示该平台账号。

## R7 功能不支持状态

不同平台可以不支持某些功能。页面不能静默隐藏主菜单，也不能只灰置按钮而无说明。

必须统一展示：

- 当前平台。
- 当前功能。
- 接入状态。
- 不支持原因。
- 下一步操作或配置入口。

验收：

- Given 当前平台为 WhatsApp，When 打开目标号互动，Then 页面显示“当前平台暂不支持此功能”。
- Given 当前平台为 Instagram 且养号执行器未接入，When 打开养号任务，Then 页面显示预留状态，不允许启动。

## R8 后端能力校验

前端禁用不是安全边界。后端必须基于 `platform + capability` 校验执行能力。

能力包括：

- accountManagement
- browserProfile
- warmupTask
- targetEngagement
- scheduler
- comments
- records
- stats
- gmailSetup
- diagnostics

验收：

- Given 通过接口直接请求运行 Instagram 养号但平台未接入，Then 后端拒绝并返回明确错误。
- Given TikTok 已支持养号，When 后端收到 TikTok 养号请求，Then 继续执行启动前检查。

## R9 平台 adapter

新增平台时必须通过平台 adapter 注册能力，而不是在页面和执行层散落条件判断。

adapter 至少描述：

- 平台 ID。
- 平台名称。
- 平台状态。
- 能力矩阵。
- 默认任务参数。
- 页面配置 schema。
- 执行器入口。
- 统计口径。
- 日志解析规则。

验收：

- Given 新增一个平台 adapter，When 注册到平台 registry，Then 顶部平台选择器可显示该平台。
- Given 平台未实现某能力，When 进入对应页面，Then 使用统一不支持状态。

## R10 迁移与兼容

必须兼容现有 TikTok V1 数据。

迁移要求：

- 老账号缺少 platform 时默认补 `platform: tiktok`。
- 旧 `defaults.daily_actions` 迁移或映射到 TikTok 养号配置。
- 旧 `target_accounts` 迁移或映射到 TikTok 目标号互动配置。
- 旧评论池 `comments.txt`、`comments_brand.txt` 默认归属 TikTok。
- 旧执行记录如缺 platform，可通过账号 ID 或历史兼容规则推导为 TikTok，并在新写入时显式写入 platform。

验收：

- Given 老配置文件，When 应用加载，Then TikTok 功能仍可正常显示和运行。
- Given 老 actions.db，When 打开统计报表，Then 历史 TikTok 数据仍可查询。

## 完成定义

本改造完成时必须满足：

- 左侧导航稳定，不随平台数量增长。
- 顶部平台选择器能明确控制当前平台上下文。
- 写操作页面严格跟随当前平台。
- 汇总页面默认全平台，并支持平台筛选。
- 平台设置入口从顶部进入。
- 数据结构、后端接口、执行记录具备 platform 维度。
- 未接入平台不能被误启动。
- 新增平台只需注册 adapter 并补齐对应页面/执行能力，不需要重构左侧导航。
