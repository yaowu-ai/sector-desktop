# 平台自动登录 V1 Requirements

## 背景

当前养号任务默认假设浏览器 profile 已经登录目标平台。用户启动任务后，脚本打开对应 profile 并直接执行 FYP 浏览、点赞、关注、评论或目标号互动。如果 profile 未登录、登录态过期，或平台跳转到登录页，任务会失败或停留在不可执行状态。

为了降低用户维护成本，桌面端需要支持平台自动登录能力：启动养号任务后，程序先打开对应平台，检测当前登录状态；如果已登录，则继续任务；如果未登录或弹出登录页面，则自动填写账号凭据并尝试登录；登录成功后继续养号任务。遇到验证码、二次验证、安全确认等无法稳定自动处理的场景时，程序必须暂停并提示用户人工接管。

## 目标

- 在养号任务启动前自动检测平台登录状态。
- 支持未登录时自动打开登录页、填写账号和密码并提交。
- 登录成功后继续执行原养号任务。
- 在账号管理页面支持录入和维护登录账号信息。
- 密码不得以明文保存到 `accounts.yaml`、日志、命令行参数或配置备份中。
- 支持人工接管验证码、二次验证、安全检查和异常登录确认。
- 以平台 adapter 方式实现，避免把 TikTok 登录逻辑硬编码进通用任务流程。

## 非目标

- 不承诺自动绕过验证码、二次验证或平台风控。
- 不实现短信验证码、邮箱验证码的自动读取。
- 不存储平台 session cookie 的独立同步系统。
- 不实现云端凭据托管。
- 不改变现有养号动作策略。
- 不把用户密码暴露给前端日志、导出诊断包或配置备份。

## 用户角色

- 运营人员：维护账号登录信息，启动养号任务，遇到异常登录时进行人工接管。
- 技术维护人员：配置凭据存储、诊断自动登录失败原因、维护平台登录 adapter。

## 产品需求

### R1 账号管理支持登录信息

账号新增和编辑页面必须支持维护平台登录信息。

字段：

- 自动登录开关。
- 登录账号，支持邮箱、用户名或手机号。
- 密码录入/更新入口。
- 凭据状态，显示是否已保存密码，但不回显密码。
- 登录方式，V1 可默认 `password`。
- 最近一次登录检测结果。
- 最近一次自动登录结果。

验收：

- Given 用户新增账号，When 开启自动登录，Then 页面要求填写登录账号并录入密码。
- Given 用户编辑已有账号，When 密码已保存，Then 页面只显示“已保存”，不显示明文密码。
- Given 用户清空或删除密码，Then 后续自动登录前提示缺少凭据。
- Given 自动登录关闭，Then 任务只检测登录态，不自动输入账号密码。

### R2 密码安全存储

密码不得写入普通 YAML 配置或日志。V1 必须使用本机安全凭据存储。

推荐优先级：

1. Windows Credential Manager。
2. Windows DPAPI 加密文件。
3. 仅开发模式允许环境变量或临时输入。

验收：

- Given 用户保存密码，Then `accounts.yaml` 中只保存 `credential_ref`，不保存密码明文。
- Given `config/backups/` 产生配置备份，Then 备份中不包含密码明文。
- Given 任务启动，Then 密码不出现在命令行参数中。
- Given stdout/stderr/session log 记录登录过程，Then 密码被脱敏或完全不输出。

### R3 登录状态检测

任务启动后，自动化流程必须先检测当前平台是否已登录。

状态：

- `logged_in`
- `logged_out`
- `login_page`
- `mfa_required`
- `captcha_required`
- `security_check_required`
- `unknown`

验收：

- Given profile 已登录 TikTok，When 任务启动，Then 跳过自动登录并继续养号。
- Given profile 未登录，When 任务启动，Then 进入自动登录流程。
- Given 平台显示验证码或二次验证，When 检测登录状态，Then 任务进入人工接管状态。
- Given 登录状态无法判断，Then 页面显示 unknown，并允许用户人工检查。

### R4 自动登录流程

当账号启用自动登录且缺少登录态时，系统应尝试自动登录。

流程：

1. 打开平台首页或登录页。
2. 定位登录账号输入框。
3. 输入登录账号。
4. 定位密码输入框。
5. 输入密码。
6. 提交登录。
7. 等待登录完成。
8. 重新检测登录状态。
9. 登录成功后继续养号任务。

验收：

- Given 自动登录开启且凭据完整，When profile 未登录，Then 脚本自动填写账号密码并提交。
- Given 登录成功，Then 继续执行原任务。
- Given 登录失败，Then 任务停止或进入人工接管，并记录失败原因。
- Given 页面结构变化导致输入框无法定位，Then 任务返回明确错误。

### R5 人工接管

遇到无法稳定自动完成的登录步骤时，应用必须进入人工接管状态。

人工接管场景：

- 验证码。
- 二次验证。
- 邮箱确认。
- 手机短信确认。
- 安全问题。
- 异常设备确认。
- 需要用户同意新条款。

验收：

- Given 自动登录遇到验证码，Then 任务暂停并显示需要人工处理。
- Given 用户在浏览器里手动完成验证，When 点击“继续检测登录状态”，Then 应用重新检测登录状态。
- Given 检测到已登录，Then 继续养号任务。
- Given 用户取消接管，Then 当前账号任务结束并记录状态。

### R6 平台 AuthAdapter

自动登录必须按平台 adapter 实现，不能写成单一平台硬编码流程。

每个平台 adapter 至少定义：

- `detect_login_state`
- `open_login_page`
- `fill_credentials`
- `submit_login`
- `detect_intervention_required`
- `wait_until_logged_in`

验收：

- Given 当前平台为 TikTok，Then 使用 TikTok AuthAdapter。
- Given 当前平台未实现 AuthAdapter，Then 后端明确提示该平台不支持自动登录。
- Given 后续新增平台，Then 通过新增 AuthAdapter 接入，不修改通用任务流程。

### R7 任务流程集成

养号任务必须在执行动作前调用登录保障流程。

目标流程：

```text
BrowserProvider.open_profile(account)
AuthAdapter.ensure_logged_in(account, browser_session)
WarmupTask.run(account, browser_session)
```

验收：

- Given 登录态有效，Then `ensure_logged_in` 快速通过。
- Given 登录态缺失且自动登录成功，Then 后续任务继续运行。
- Given 自动登录失败，Then 不执行后续点赞、关注、评论等动作。

### R8 配置兼容

旧账号配置必须继续可用。

验收：

- Given 旧 `accounts.yaml` 没有 `login` 字段，Then 账号默认 `login.enabled=false`。
- Given 账号已配置 BitBrowser profile 但未配置登录凭据，Then 仍可按原逻辑运行已登录 profile。
- Given 用户开启自动登录但未保存密码，Then 保存或运行前提示补齐凭据。

### R9 诊断与审计

系统必须提供登录诊断和安全审计信息。

验收：

- 账号详情显示最近登录状态检测时间和结果。
- 任务日志记录登录流程状态，但不记录密码。
- 诊断页可测试“检测登录状态”。
- 诊断页可测试“自动登录”，并要求二次确认。
- 支持删除某账号保存的凭据。

## 完成定义

平台自动登录 V1 完成时，用户可以在账号管理中录入登录账号并安全保存密码；启动养号任务后，系统先检测登录态，已登录则直接运行，未登录则自动尝试登录；遇到验证码或二次验证时进入人工接管；登录成功后继续原任务；所有密码都不进入 YAML、日志、命令行参数或配置备份。
