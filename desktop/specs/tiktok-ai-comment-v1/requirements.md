# TikTok AI 评论 V1 Requirements

## 背景

当前 TikTok 养号任务的评论能力依赖评论池：脚本在满足评论概率和评论数门槛后，从用户预先维护的评论素材中随机选择一句，并对当前视频发表评论。

随着 FYP 视频信息采集能力加入，系统可以拿到当前视频的标题或描述。基于这些上下文，可以生成更贴合视频内容的一句短评论，降低固定评论池带来的重复和不相关问题。

本需求新增“AI 评论”高级功能。用户在 PC 端自行配置 Kimi Moonshot API Key，开启后，养号任务评论时优先根据当前视频标题/描述生成评论；关闭或生成失败时，仍使用原评论池逻辑。

## 目标

- 在评论素材页面增加 `AI 评论` 高级开关和配置入口。
- 支持用户自填 Kimi Moonshot API 配置。
- 在 TikTok FYP 养号任务需要评论时，根据当前视频标题/描述生成一句评论。
- AI 评论失败、超时、内容校验不通过或视频信息不足时，自动回退评论池。
- 保持原评论池能力和默认行为不变。
- 记录评论来源，便于排查和统计。
- 默认接入 Kimi Moonshot，但实现结构应方便以后切换其他模型 API。

## 非目标

- 不默认启用 AI 评论。
- 不要求用户必须配置大模型 API 才能使用原评论池。
- 不实现复杂多轮 agent、长期记忆、账号人格或自动策略优化。
- 不在 V1 中提供服务端统一模型代理。
- 不在 V1 中支持本地 Ollama / LM Studio。
- 不生成多条候选让脚本自行长时间筛选。
- 不绕过平台风控或承诺提高账号安全性。

## 功能要求

### R1 AI 评论开关

评论素材页面必须提供 `AI 评论` 高级开关。

验收：

- 默认关闭。
- 关闭时，FYP 评论逻辑完全沿用原评论池。
- 开启时，评论前优先尝试 AI 生成评论。
- 开关状态应保存在本机配置中。
- 页面必须明确说明：AI 评论失败会回退评论池。

### R2 用户自填模型配置

用户必须能在 PC 端配置自己的大模型 API。

验收：

- 支持 Kimi Moonshot API。Kimi 接口兼容 OpenAI Chat Completions 协议，运行时按兼容协议调用。
- 至少包含 `base_url`、`model`、`api_key`、`timeout_seconds`。
- `api_key` 不得明文写入 `accounts.yaml` 或评论文件。
- API Key 应使用已有本机安全凭据存储或系统设置加密存储。
- 支持测试连接按钮。
- 测试连接必须只发送最小测试请求，不读取用户账号数据。

推荐配置字段：

```yaml
ai_comment:
  enabled: true
  provider: kimi_moonshot
  base_url: https://api.moonshot.cn/v1
  model: kimi-k2.6
  timeout_seconds: 5
  max_comment_length: 80
  fallback_to_pool: true
```

### R3 评论生成输入

AI 评论生成必须只使用必要上下文。

验收：

- 输入包含当前视频 `title` 或 `description`。
- 可选输入包含平台、语言偏好、评论长度要求。
- 不传入账号密码、Cookie、Token、代理、CDP 地址、用户本机路径。
- 视频标题和描述为空时不调用 AI，直接回退评论池。

推荐输入：

```json
{
  "platform": "tiktok",
  "title": "视频标题",
  "description": "视频描述",
  "language": "auto",
  "maxLength": 80
}
```

### R4 评论生成输出

AI 必须只返回一句可直接发布的短评论。

验收：

- 输出必须为单句文本。
- 不允许包含换行、多条编号、解释、引号包装。
- 不允许包含链接、联系方式、明显营销话术、@ 用户。
- 长度必须限制，默认不超过 80 字符。
- 输出为空或校验失败时回退评论池。

### R5 FYP 评论流程接入

FYP 养号任务命中评论动作时，应按配置选择评论来源。

验收：

- AI 评论关闭：沿用 `random.choice(comments_pool)`。
- AI 评论开启且当前视频有标题/描述：调用 AI 评论生成器。
- AI 生成成功且通过校验：使用 AI 评论。
- AI 生成失败、超时、异常、校验失败：从评论池取评论。
- 如果评论池也为空，则按现有逻辑跳过评论。
- AI 生成不应改变评论概率、评论目标数、评论数门槛。

### R6 超时和失败处理

AI 调用必须有短超时和明确回退。

验收：

- 默认超时 5 秒。
- 超时后不重试或最多轻量重试 1 次。
- 失败不影响 FYP 浏览继续。
- 失败不影响 `fyp_browse videos=N` 汇总记录。
- 失败原因应脱敏后记录到日志或动作明细。

### R7 评论来源记录

系统必须记录实际使用的评论来源。

验收：

- AI 评论成功时记录 `comment_source=ai`。
- 回退评论池时记录 `comment_source=pool` 和简短原因。
- 未评论时不强行记录评论文本。
- 不在普通执行记录中暴露 API Key 或完整请求体。

### R8 评论素材页面 UI

评论素材页面必须能管理 AI 评论配置。

验收：

- 保留原评论池编辑能力。
- 新增高级区域 `AI 评论`。
- 支持开关、Base URL、Model、API Key 保存、超时、最大评论长度。
- 支持测试连接。
- 支持一条“根据示例标题生成评论”的测试能力。
- 密钥输入默认隐藏。
- 未配置 API Key 时，开启开关必须给出明确提示。

### R9 内容安全校验

AI 评论发布前必须做基础校验。

验收：

- 过滤空文本。
- 过滤多行文本。
- 过滤 URL。
- 过滤 `@` 提及。
- 过滤明显联系方式。
- 过滤超过最大长度的文本。
- 可配置敏感词黑名单。
- 校验失败必须回退评论池。

### R10 兼容性

新增 AI 评论不能破坏已有评论池和养号能力。

验收：

- 旧配置没有 `ai_comment` 时，行为等同 AI 评论关闭。
- 评论池页面原保存、读取、去重能力保持可用。
- 现有 FYP 评论统计仍正常。
- 没有网络或 API Key 错误时，任务仍可使用评论池。
- AI 评论模块不可用时，不影响点赞、关注、浏览。

### R11 模型 API 可替换性

AI 评论默认使用 Kimi Moonshot，但实现不能把 Kimi 请求逻辑散落在 FYP 评论流程、UI 页面或评论校验中。

验收：

- 配置中必须保留 `provider`、`base_url`、`model` 字段。
- Kimi Moonshot 作为默认 provider：`provider=kimi_moonshot`。
- 底层请求适配应抽象为 provider adapter 或等价结构。
- FYP 评论流程只能调用统一的 `generate_ai_comment` 接口，不直接关心具体模型厂商。
- 如果以后切换到兼容 OpenAI Chat Completions 协议的模型 API，应只需要改配置或新增少量 provider 映射。
- 如果以后切换到非兼容协议的模型 API，应只需要新增 adapter，不改评论池 fallback、内容校验和 FYP 评论决策逻辑。

## 完成定义

- 用户可在评论素材页面配置并测试 Kimi Moonshot API。
- 用户开启 AI 评论后，FYP 评论时能根据当前视频标题/描述生成评论。
- 生成失败时自动回退评论池。
- 关闭 AI 评论时，原评论池逻辑完全不变。
- 评论来源和失败原因可追踪。
- API Key 不明文写入普通配置文件。
- 后续更换兼容 Chat Completions 的模型 API 时，不需要重写 FYP 评论业务流程。
