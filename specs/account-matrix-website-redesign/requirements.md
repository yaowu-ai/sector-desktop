# Account Matrix 官网视觉改版需求文档

## 1. 背景

当前 `website/` 已包含产品官网页面：

- `/`
- `/features`
- `/pricing`
- `/download`
- `/docs`
- `/contact`

官网已经使用 Next.js、React、Tailwind CSS 和 `motion`。本次改版聚焦官网所有公开页面的视觉设计、信息层级和转化体验，不改变后端 API、管理后台权限、License、支付等服务端能力。

## 2. 目标

官网需要从通用 SaaS 视觉升级为更贴合 Account Matrix 产品定位的官网：

- 传达 TikTok 矩阵账号运营、环境隔离、自动化任务和增长数据的产品属性。
- 保留清晰可信的 B2B SaaS 信息结构。
- 首屏直接展示产品场景，而不是抽象装饰。
- 全站页面在色彩、按钮、卡片、导航、CTA 和插画/面板语言上保持一致。
- 在视觉上有辨识度，但不能过度赛博、游戏化或牺牲可读性。

## 3. 设计方向

整体采用“深色科技产品官网”方向：

- 主背景：深墨色、近黑、深蓝黑。
- 主色：青绿色，用于关键按钮、状态、强调数据和任务进度。
- 辅助色：少量蓝紫，用于数据图表、状态区分和光效层次。
- 产品视觉：账号矩阵、环境隔离、任务队列、执行状态、数据看板、自动化流程。
- 信息组织：参考成熟 SaaS 官网的清晰结构，避免只做视觉展示。

最终风格应是：

```text
产品气质：偏图 1，科技、自动化、控制台、任务流
页面结构：偏图 2，清晰、克制、转化路径明确
```

## 4. 页面范围

本次改版覆盖所有公开官网页面：

- 首页 `/`
- 功能页 `/features`
- 价格页 `/pricing`
- 下载页 `/download`
- 文档页 `/docs`
- 联系页 `/contact`

共享组件和样式也在范围内：

- `Navbar`
- `Footer`
- 全局 CSS
- 按钮样式
- 卡片样式
- CTA 区域
- 表格和价格卡
- FAQ 和文档模块
- 产品预览面板

不在本次范围：

- `/admin/*` 管理后台业务页面。
- `/api/*` 接口行为。
- 登录、订阅、支付、License 服务逻辑。
- 数据库模型和鉴权能力。

## 5. 用户需求

### 5.1 官网访客

作为一个准备做 TikTok 矩阵运营的访客，我需要在首屏看出 Account Matrix 是什么、解决什么问题，以及是否适合我的运营场景。

验收标准：

- 首页首屏必须明确出现产品名、核心价值主张和主要 CTA。
- 首屏必须包含产品化视觉，例如账号矩阵、环境隔离、任务执行状态或数据面板。
- 不能只展示抽象渐变、几何图形或通用 SaaS 插画。

### 5.2 运营负责人

作为团队负责人，我需要快速理解产品能否提升账号运营效率、降低封控风险并支持批量化流程。

验收标准：

- 首页和功能页必须展示批量账号管理、浏览器环境隔离、代理/profile 管理、自动任务、目标号互动和数据复盘等能力。
- 功能描述需要直接对应运营工作流，而不是泛泛描述“高效、智能、协作”。
- 页面需要提供清晰的下一步入口，例如查看功能、下载、咨询或查看价格。

### 5.3 购买决策者

作为购买决策者，我需要清楚理解套餐差异、适用规模、能力边界和联系入口。

验收标准：

- 价格页必须保持套餐对比清晰。
- 价格卡和对比表在深色风格下仍要易读。
- 关键差异如账号额度、设备额度、自动调度、目标互动、CSV 导出、团队席位必须突出。

### 5.4 新用户

作为新用户，我需要知道如何下载、安装、启动和获得支持。

验收标准：

- 下载页必须突出当前版本、更新时间、平台、下载 CTA 和安装步骤。
- 文档页必须提供启动流程、常见问题和关键概念说明。
- 联系页必须清晰展示咨询、售后、企业合作和问题反馈入口。

## 6. 内容需求

### 6.1 首页

首页应包含：

- Hero：产品名、核心价值主张、主 CTA、次 CTA、产品控制台视觉。
- 信任或成果区：自动化执行、账号规模、任务稳定性、数据追踪等指标。
- 核心能力区：环境隔离、任务编排、目标互动、素材池、风控提示、数据复盘。
- 工作流区：导入账号、配置环境、创建任务、运行监控、复盘优化。
- 产品场景区：账号矩阵表、任务队列、执行进度、异常提示。
- CTA 区：下载、查看价格、联系咨询。

### 6.2 功能页

功能页应按运营工作流组织，而不是只按功能卡片堆叠：

- 账号与环境。
- 任务自动化。
- 目标号互动。
- 素材与评论池。
- 数据与复盘。
- 团队与权限。
- 风险控制和排障。

### 6.3 价格页

价格页应包含：

- 套餐卡片。
- 适用人群。
- 核心额度。
- 功能对比表。
- 企业咨询 CTA。
- 常见付费问题。

### 6.4 下载页

下载页应包含：

- 当前版本。
- 平台说明。
- 下载 CTA。
- 安装步骤。
- 更新说明。
- 系统要求。
- 安全和数据说明。

### 6.5 文档页

文档页应包含：

- 快速开始。
- 概念说明。
- 常见操作流程。
- FAQ。
- 故障排查入口。

### 6.6 联系页

联系页应包含：

- 售前咨询。
- 企业合作。
- 技术支持。
- 问题反馈。
- 联系方式或表单。

## 7. 视觉需求

- 全站应使用同一套深色视觉系统。
- 所有页面顶部和底部必须统一。
- CTA 按钮必须有明确主次层级。
- 卡片不应过度圆角，建议 8px 到 14px 之间，除非产品面板需要特殊处理。
- 背景可使用网格、扫描线、柔和光效，但不能影响文本可读性。
- 不使用大面积单一紫色或纯蓝渐变作为主视觉。
- 不使用与产品无关的抽象 3D 装饰作为首屏主视觉。
- 产品预览应更像真实控制台，而不是纯装饰卡片。
- 中文内容需要在移动端和桌面端都不溢出。

## 8. 交互和响应式需求

- 全站必须支持桌面、平板和手机。
- 导航在移动端必须可用。
- 表格在移动端需要可横向滚动或转为卡片布局。
- 价格卡在移动端应保持清晰，不压缩到难读。
- 动效应增强状态感和层次感，不能阻碍阅读。
- `prefers-reduced-motion` 下应减少或禁用非必要动画。

## 9. 技术约束

- 优先使用现有 Tailwind CSS。
- 优先使用已有 `motion`，暂不引入新的动效库。
- 不优先引入 shadcn、Ant Design 或大型 UI 组件库来改官网。
- 可以新增轻量工具函数或共享展示组件。
- 不改变公开 API 的响应结构，除非另有单独需求。
- 不改变管理后台目录和权限设计。

## 10. SEO 和可访问性需求

- 保留每个公开页面的 metadata。
- 页面标题层级必须合理，每页只有一个主要 H1。
- 关键链接和按钮必须有可理解文本。
- 颜色对比度必须满足正常阅读。
- 产品截图或视觉面板如果是图片，必须提供 `alt`。
- 不把重要内容只放在图片里。

## 11. 验收标准

改版完成后需要满足：

- 六个公开页面视觉统一。
- 首页首屏明确表达“TikTok 矩阵运营自动化工具”。
- 页面主体包含产品化控制台/任务流/数据面板视觉。
- 价格、下载、文档、联系页面保持清晰可用，不只是换皮。
- 桌面和移动端无明显文本溢出、元素重叠或按钮不可点。
- `pnpm typecheck` 通过。
- 构建或本地运行无阻塞性错误。
